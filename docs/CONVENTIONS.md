# 설계·구현 컨벤션 인덱스

이 문서는 사람과 AI가 같은 기준으로 설계하고 검토하기 위한 진입점이다. 규칙을 많이 만드는 것이 목적이 아니라, 반복해서 판단하는 경계와 그 근거를 명확히 하는 것이 목적이다.

## 사용 순서

판단 우선순위는 다음과 같다.

1. 사용자의 현재 지시와 기능 요구사항
2. 실제 API 계약, 타입, 패키지와 설정
3. 이 인덱스와 관련 상세 문서의 기본 규칙
4. 주변 코드의 일관된 방식

컨벤션은 기본값이다. 요구사항 때문에 예외를 선택하면 무엇을 바꿨고, 왜 더 정확하며, 무엇으로 검증했는지 작업 기록이나 PR에 짧게 남긴다.

## 핵심 철학

1. 늘 이해하기 쉽게 작성한다.
2. 책임과 데이터 흐름을 명확히 한다.
3. 기술 선택에는 근거가 있어야 한다.
4. 정확성을 우선하고 최적화는 근거가 있을 때 적용한다.
5. 검증 가능한 코드를 작성한다.
6. AI는 구현과 판단을 뒷받침하며 최종 결정은 개발자가 한다.

## 규칙 문서 형식

설계 판단이 필요한 규칙은 가능한 한 다음 순서로 작성한다.

1. 규칙
2. 이유
3. 적용 조건과 예시
4. 예외

비직관적인 규칙에는 올바른 예와 피해야 할 예를 함께 둔다. 프레임워크 동작을 근거로 삼는 규칙에는 공식 문서 링크를 가까이 둔다. 예시와 근거를 제거한 짧은 명령만으로 축약하지 않는다.

## 의도적으로 강제하지 않는 것

- 파일의 최대 줄 수와 폴더의 고정 깊이
- 모든 로직의 custom hook 분리
- 사용 횟수에 따른 자동 공통화
- 모든 컴포넌트의 메모이제이션
- 고정된 전역 cache 시간과 재시도 횟수
- 100% 테스트 coverage
- 모든 상태를 Zustand에 저장하는 방식
- 미래 상태관리 교체를 위한 공통 adapter
- 아직 필요하지 않은 빈 폴더와 추상화 계층

새 규칙은 실제로 같은 문제가 반복될 때 추가한다. 한 기능에만 필요한 선택은 공통 컨벤션보다 해당 코드와 작업 기록 가까이에 둔다.
