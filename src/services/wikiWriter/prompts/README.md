# 단톡위키 LLM 프롬프트

이 폴더의 Markdown이 Gemini에 보내는 지시문의 원본이다. 코드 수정 없이 문장을 고쳐 결과를 조정할 수 있다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `style.md` | 모든 문서에 공통으로 붙는 문체·사실성·표기 규칙 (system instruction) |
| `room/_document.md` | 단톡방 문서 전체에 대한 지시 |
| `room/<섹션 key>.md` | 단톡방 문서의 해당 섹션을 쓸 때의 지시 |
| `person/_document.md` | 인물 문서 전체에 대한 지시 |
| `person/<섹션 key>.md` | 인물 문서의 해당 섹션을 쓸 때의 지시 |

## 규칙

- **`.md` 파일이 있는 섹션만 LLM이 쓴다.** 파일을 지우면 그 섹션은 규칙 기반 문장으로 돌아가고, 섹션 key로 파일을 추가하면 LLM 대상이 된다.
- 단톡방 섹션 key는 `src/screens/home/utils/roomWiki/sections*.ts`의 `section(ctx, "<key>", ...)` 값이다. (`related`는 링크 목록이라 파일을 두지 않았다. 통계·어워즈·연감·유형 도감·분석 기준 섹션은 문서에서 뺐다.)
- 인물 섹션 key는 `overview`, `traits`, `nicknames`, `quotes`, `relationships`, `trivia`다.
- 표 일부는 LLM이 서술 대신 구조화된 값으로 채운다: 개요 > 기본 정보의 관계·화제·분위기·시기명(`overviewInfo`), 역사 > 주요 사건 연표의 행(`timeline`), 역사 시기의 시기명(하위 문단 `title`). 명칭 > 역대 방 이름은 시스템 메시지로 확인한 표라 서술로 바뀌지 않는다(`buildProseRequest.ts`의 `FACTS_ONLY_SUBS`). 멤버 > 멤버 관계도는 원본 숫자 표뿐이라 LLM에 보내지 않는다(`RULE_ONLY_SUBS`).
- 멤버·상징·유행어의 표 칸(한 줄 캐릭터, 역할, 뜻·쓰임, 주로 쓰이는 상황, 웃음 시그니처 등)은 LLM이 하위 문단의 `rows`로 채운다. 어느 표의 어느 칸인지, LLM이 고른 행만 남길지는 `wikiWriter.schema.ts`의 `AI_TABLE_SUBS`가 정한다. 유행어 표는 LLM이 방 고유 유행어·외부 밈으로 분류한 행만 남는다.
- 멤버별 특징·멤버 간 케미·의외의 조합·유행어의 기원·멤버별 말버릇은 LLM이 하위 문단의 `parts`로 멤버·쌍·유행어마다 소제목(`==== 제목 ====`)을 단다(`AI_PARTS_SUBS`).
- 방의 성격과 문화·주요 에피소드·논란 및 사건·사고(`ITEM_SECTION_KEYS`)는 규칙 기반 하위 문단을 사실 묶음 하나로 합쳐 보내고, LLM이 정한 항목(제목·날짜·본문·하위 문단)으로 섹션 전체를 바꾼다. 명예의 전당은 구성원마다 하위 문단 하나를 두고 LLM이 제목과 본문을 쓴다.
- LLM은 각 하위 문단의 서술을 쓴다. LLM이 쓴 하위 문단에서는 서술이 본문이 되고, 자동 문장·목록·표·막대는 하위 문단 끝의 "통계 펼치기"로 접힌다(그 숫자는 "사실"로 이미 넘겼다). 인용 상자·시간대 차트·대화 장면·소제목은 본문에 남는다. `AI_TABLE_SUBS`·`KEEP_TABLE_SUBS`의 표와 접힌 표(원본 행렬 등)도 남는다. LLM이 쓰지 않은(빈 배열을 준) 하위 문단은 규칙 기반 문장과 목록이 그대로 남는다. 묶음 요청 자체가 실패한 섹션·인물 문서에는 "AI 서술을 불러오지 못해 통계로만 작성되었습니다" 안내가 붙는다.
- LLM 출력에서 앱이 해석하는 표기는 `**굵게**`, `~~취소선~~`, `[[이름]]`, `[* 각주]`, `> 이름: 메시지`(대화 장면), 대화 장면을 감싼 `{{{#!folding [ 제목 ]` … `}}}`(접기), `[[#YYYY-MM-DD|문구]]`(그 날짜를 다룬 에피소드·논란 항목으로 가는 링크)뿐이다. 새 표기를 프롬프트에 추가하려면 `src/screens/home/utils/aiProse/applyProse.ts`도 함께 고쳐야 한다.
- 각주와 대화 장면 인용은 서버가 실제로 보낸 발췌와 대조해, 일치하지 않으면 지운다(`verifyQuotes.ts`).
- LLM에는 원본 전체가 아니라 아래 자료만 보낸다(`sampleExcerpts.ts`, 합계 900줄 이하). 전화번호·계좌번호·이메일·주민번호와 링크는 브라우저에서 미리 가린다.
  - 연속된 대화 장면: 대화 파일의 첫 티키타카 `[첫 기록]`, 마지막 5줄 `[마지막 기록]`, 해명·소문·정정 표현이나 긴 침묵 뒤 대화의 앞뒤 `[사건 후보]` 10개 이하, 친밀도 상위·의외의 조합 쌍이 둘만 주고받은 대화 `[두 사람 대화]`, 유행어의 첫 등장 `[유행어 첫 등장]`과 마지막 사용 `[유행어 마지막 사용]`, 가장 길게 웃은 장면 `[최장 웃음]`, 그리고 시기별로 고른 장면.
  - 한 줄 발췌: 방 이름·방 지칭 20줄(명칭), 관행 단서 24줄(방의 성격과 문화), 유행어 사용 45줄·호칭 24줄·이모지 21줄(상징·유행어), 구성원별 발췌(나머지 자리).
- 토큰을 줄이려고 묶음마다 필요한 발췌만 보낸다. 단톡방 묶음은 그 묶음 섹션들이 쓰는 발췌 종류(`wikiWriter.schema.ts`의 `SECTION_EXCERPTS`)만, 인물 묶음은 그 사람들의 한 줄 발췌와 그 사람들이 말한 장면만 받는다(`splitProseJobs.ts`). 섹션 지시문에 새 발췌 종류를 근거로 쓰게 하면 `SECTION_EXCERPTS`에도 추가해야 한다. 한 줄 발췌는 말한 사람별로 묶어 이름과 날짜를 한 번만 쓴다. 요청마다 실제 토큰 수가 서버 로그 "[단톡위키] Gemini 토큰"에 남는다.
- 입장·퇴장·초대·내보내기·방 이름 변경은 파서가 시스템 메시지에서 읽는다(`parseChat.ts`의 `readMemberEvents`). 멤버 상태·합류일·인원 변천사와 역대 방 이름의 근거다.
- 문서를 읽는 사람은 일반 독자다. 친밀도 지수·정규화 값·배율처럼 해석이 필요한 계산값은 규칙 기반 문서에서 `facts` 블록(`builder.ts`의 `facts()`)으로 두어 LLM에게만 보내고, 화면에는 그리지 않는다. AI 서술을 입힌 뒤 문서에서 뺀다.
- 근거가 없는 하위 문단은 "없다"고 쓰지 않고 문서에서 뺀다. 규칙 기반으로 보여 줄 것이 없으면 `build`가 null을 돌려주고, LLM이 응답한 섹션에서 LLM이 비워 둔 하위 문단도 뺀다(`applyProse.ts`의 `keepsWithoutProse`가 남길 예외를 정한다).
- 같은 일화가 여러 섹션에 되풀이되지 않게 묶음을 순서대로 보낸다(`writeAiProse.ts`의 `COVER_ORDER`). 에피소드·논란·멤버 → 개요·명칭·역사·문화·유행어 → 명예의 전당·여담 순이고, 뒤 순서 묶음은 앞에서 다룬 사건 제목·인용 목록(`covered`)을 받아 다시 풀어 쓰지 않는다. 에피소드·논란 항목은 날짜순으로 정렬한다.
- `_`로 시작하는 파일과 이 README는 섹션으로 취급하지 않는다.
- 파일은 서버가 처음 요청을 받을 때 읽고 메모리에 보관한다. 개발 서버에서는 수정 후 서버를 재시작하면 반영된다.
